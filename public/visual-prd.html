Product thesis Generation is not assurance.

Tests become trustworthy only when Bandersnatch understands the application, validates that each platform exposes compatible semantics, observes the release build, and links every equivalence decision to evidence.

Product principles

The roadmap protects the original intent-first mechanic while moving from a controlled demo to a release-assurance platform.

01Intent before selectors

Journeys describe semantic actions and observable outcomes. Platform bindings remain replaceable implementation details.

02Compatibility before execution

Linting and onboarding reveal missing identifiers, accessibility semantics, reset paths, and unobservable results before cloud resources are spent.

03Release evidence is truth

Source and commits forecast impact. Only observed release artifacts can update the certified experience graph.

04Equivalence, not sameness

Different interfaces can be equivalent when they allow the same job to complete with compatible outcomes and accessibility.

Smallest complete platform

Voice and NLP are input adapters. The durable core is the contract, experience graph, platform execution, normalized evidence, and comparator.

1 · Product intent

Natural language, scenario library, requirements, or an AI coding agent proposes a journey.

2 · Compatibility layer

Lint rules and repository mappings make controls, states, and outcomes discoverable.

3 · Experience graph

A release-versioned graph connects semantic concepts to Android, iOS, and Web implementations.

4 · Platform execution

Maestro runs mobile builds; Playwright runs Web. All runners publish normalized evidence.

5 · Assurance

The comparator produces equivalent, divergent, or incomparable with the first meaningful divergence.

Bandersnatch compatibility

A semantic lint contract reduces discovery cost, improves accessibility, and gives developer AI agents an explicit, testable target.

Experience contract
concepts:
  coupon_code:
    type: text_input
    accessibleName: Coupon code

  apply_coupon:
    type: action
    accessibleName: Apply coupon

  discounted_total:
    type: observable
    valueType: money
    announcement: polite
First rule set
BS001Required semantic concept has no stable platform identifier.
BS002Interactive concept has no accessible human-readable name.
BS005Journey performs an action but exposes no observable outcome.
BS006State changes visually but is not announced programmatically.
BS007A required concept is missing from one or more platforms.
BS010Journey destination has no deterministic reset or entry strategy.

The defensible layer

The long-term asset is not generated scripts. It is the living, evidence-backed relationship between product intent and every platform implementation.

Bandersnatch becomes the semantic index of the product experience.
It knows what a journey means, where each concept lives, which release proved it, what changed, what must be re-tested, and whether every platform still delivers the same job.
Product intentRequirements, natural language, and approved journey contracts.
Semantic conceptsActions, destinations, values, states, announcements, and outcomes.
Platform implementationsAndroid, iOS, and Web source components and runtime controls.
Release provenanceCommits, artifact hashes, deployments, configuration, and graph versions.
Observed evidenceVideos, traces, hierarchies, screenshots, normalized values, and completion modes.
Assurance historyEquivalence decisions, accepted variance, regressions, and consistency debt.
